# Решения по ходу работы

Здесь записаны детали, которые SPEC.md оставил открытыми, и выбранный вариант.
Новые решения добавляются в конец раздела своего этапа.

## Этап 0 — каркас и стиль

**Инструменты сборки.** Android Gradle Plugin 9.4.1, Gradle 9.8.2, Kotlin 2.4.21,
compileSdk и targetSdk 37 (Android 17, последний стабильный на октябрь 2026), minSdk 26.
AGP 9 компилирует Kotlin сам («built-in Kotlin»), поэтому плагин `kotlin-android` в модуле не применяется;
в корневом `build.gradle.kts` он объявлен с `apply false` только ради версии компилятора.

**Шрифт заголовков — Playfair Display SC.** ТЗ разрешает Ruslan Display или Playfair Display SC.
Ruslan Display выглядит скорее «древнерусским», чем викторианским, и плохо читается мелким кеглем.
Playfair Display SC даёт капитель в духе гравированных табличек и имеет полужирное начертание.
Кириллица у всех шрифтов проверена скриптом: все буквы, «ё», «№», кавычки-ёлочки.
Знака ₽ нет в Playfair Display SC — в заголовках он не встречается, а в основном тексте (Old Standard TT)
и цифрах (PT Mono) он есть.

**Репозиторий публичный — `google-services.json` в него не кладём.** ТЗ рассчитано на приватный репозиторий.
Раз репозиторий открыт, конфиг Firebase передаётся через секрет GitHub `GOOGLE_SERVICES_JSON`
(содержимое файла целиком); сборка сама кладёт его в `app/`. Файл добавлен в `.gitignore`.
Если сделать репозиторий приватным, можно загрузить файл и напрямую, как написано в ТЗ.

**versionCode = 1 + major·10000 + minor·100 + patch.** Тег `v0.1.0` даёт versionCode 101, `v1.2.3` — 10204.
Так номер растёт с каждым релизом и выводится из тега без отдельного счётчика.

**Подпись без секретов.** Если четырёх секретов подписи нет, release-APK подписывается отладочным ключом
сборочной машины, а в логе сборки появляется предупреждение. Такой ключ каждый раз новый, поэтому версию,
подписанную им, нельзя обновить поверх — только переустановить. Секреты нужно добавить до того,
как в приложении появятся данные (этап 1).

**Дополнительные токены палитры.** Из токенов ТЗ выведены вспомогательные: утопленная поверхность,
тень латуни, светлая медь, цвет гравировки, цвета текста на бейджах статусов, циферблат, окно одометра,
плашка выбранной вкладки. Все пары «текст — фон» проверяет тест `ContrastTest` (не ниже 4,5:1).

**Цвета статусов — только на бейджах и в графике.** В дневной теме патина (#2E7F7B) и медь (#B5651D)
дают текстом по пергаменту контраст ниже 4,5:1, поэтому статус всегда пишется на эмалевом бейдже
своего цвета, а цветом без подложки рисуются только зоны манометра.

**Тень латуни в дневной теме — #6A5A1E.** Это основной цвет кнопок Material в дневной теме;
более светлый оттенок не дотягивал до 4,5:1 на пергаменте.

**Шкала манометра — от 0 до 125 % интервала.** Зона «Норма» — до (100 % − порог), «Скоро» — до 100 %,
«Пора менять» — 100–125 %. Сильнее просроченный расходник прижимает стрелку к правому упору, и она дрожит.
Без данных стрелка лежит на левом упоре, а в окошке — табличка с вопросом.

**Фоновая текстура** (дерево или пергамент) генерируется при первом запуске, кешируется в памяти
и PNG-файлом в `cacheDir`, дальше рисуется плиткой. Это шум без внешней графики.

**Релиз ставит сама сборка.** По ТЗ после каждого этапа ставится тег `v0.<этап>.0`. Из сессии Claude Code
пушить можно только в рабочую ветку, поэтому тег ставит GitHub Actions: если верхний раздел CHANGELOG.md
(`## X.Y.Z`) описывает версию, для которой ещё нет тега, сборка ставит тег `vX.Y.Z` на этот коммит
и публикует релиз с APK. Тег, поставленный вручную, тоже даёт релиз.

**Рычаг срабатывает на 60 % хода.** При свайпе вниз рукоять идёт за пальцем; если отпустить раньше,
она пружинит назад без срабатывания.

## Этап 1 — машины и расходники

**Все таблицы — сразу в версии 1 базы.** Машины, расходники, замены, показания пробега, гараж, состояние
уведомлений и шаблоны созданы в первой же версии, хотя часть понадобится только на этапах 2 и 4.
Так не нужны миграции до первого выпуска с синхронизацией. Схема выгружается в `app/schemas/`:
по ней будут писаться миграции следующих версий.

**Пробег из записи замены — тоже показание.** Замена с пробегом добавляет показание одометра, связанное
с этой заменой. Если запись замены исправить или удалить, связанное показание меняется или удаляется вместе с ней.

**«Ошибка в прошлых данных».** Если введённый пробег меньше текущего, приложение спрашивает, что случилось.
Вариант «Ошибка в прошлых данных» удаляет все показания больше нового значения, вариант «Отмена» ничего не меняет.
Записи замен не трогаются: в них пробег вписан вручную.

**Удаление расходника не удаляет показания пробега.** Показания принадлежат машине, а не расходнику.
Замены удалённого расходника исчезают вместе с ним.

**«Провести ТО»: стоимость — по каждой строке.** В общей форме у каждого отмеченного расходника своё поле
стоимости, а деталь берётся из его карточки (поле «деталь по умолчанию»). Дата, пробег, место и заметка общие.
В форме замены одного расходника деталь можно вписать вручную.

**Манометр: в окошке — остаток, под ним — только единица.** Цифры показывают остаток по сроку, который
наступит раньше, под ними — «км» или «дн.». Если срок превышен, барабаны становятся красными, а цифры
показывают превышение. Полные слова («осталось», «просрочено на») — в строках рядом с манометром:
длинная подпись не помещалась между упорами стрелки.

**Числа не переносятся посередине.** Между разрядами стоит неразрывный пробел: «1 000 км» не разорвётся
на «1» в конце строки и «000 км» в начале следующей.

**Имя автора хранится в самой записи.** У замен и показаний есть поле «кто записал» — имя устройства
из настроек на момент записи. Так в журнале общего гаража видно автора, даже если тот потом переименует телефон.

**Шаблоны пользователя — только на этом телефоне.** «Сохранить как шаблон» запоминает список расходников
машины с интервалами. Шаблоны не синхронизируются: это личная заготовка, а не данные гаража.

**Расходник без интервалов — «Нет данных».** Если у расходника не задан ни интервал по километрам,
ни по времени, статус посчитать нельзя, и он показывается как «Нет данных» даже при наличии замен.

**Пороги «Скоро» — общие в настройках и свои у расходника.** В настройках задаются процент и границы по
км и дням для всех расходников. В карточке расходника можно указать собственный порог в км или днях,
и он заменяет общий.

**Экран «Сроки» появился уже в этом этапе.** Статусы считаются с этапа 1, поэтому вкладка «Сроки» сразу
показывает расходники всех машин по срочности. Уведомления — на этапе 2.

**Код гаража — с проверочным символом.** 19 случайных символов и 20-й проверочный из алфавита без похожих
знаков (нет O, I, L). При вводе буквы O, I, L заменяются на 0 и 1, а опечатка в одном символе
ловится сразу, без запроса к серверу. Используется на этапе 4.

**Тесты — на Java 21.** Robolectric для Android 16+ работает только на Java 21, поэтому тесты запускаются
на ней (с открытыми для Robolectric модулями JDK), а код по-прежнему компилируется под Java 17.

**Схема базы — по очереди для debug и release.** Room в обоих вариантах пишет схему в один файл
`app/schemas/…/1.json`; когда сборка шла параллельно, один вариант читал недописанный файл и падал.
Генерация кода для release теперь всегда идёт после debug. Сборка скриншотов выкладывает файл схемы,
и он хранится в репозитории в `app/schemas/`.

**Скриншоты экранов — в служебном пререлизе.** Отдельная сборка рисует основные экраны с тестовыми данными
(Robolectric + Roborazzi) и выкладывает PNG в пререлиз `ci-screenshots`. По ним проверяется внешний вид
без телефона. Устанавливать оттуда нечего.
