# ТЗ для Claude Code: «Паровой гараж» — учёт замены расходников

2026-10-23 · @Pony

## Цель и рамки

Нужно Android-приложение для учёта замены расходников автомобиля. Пользователь заводит машины, задаёт каждому расходнику интервал замены по пробегу и/или по времени, получает уведомление при приближении срока и записывает каждую замену. Общие машины синхронизируются между несколькими Android-устройствами через Firebase.

Интерфейс стилизован под стимпанк: латунь, медь, тёмное дерево, стрелочные манометры, рычаги и клёпаные таблички. Действия сопровождаются механическими звуками и короткими голосовыми фразами; и то и другое отключается в настройках.

Рабочее название — **«Паровой гараж»** (меняется одной константой и строкой в `strings.xml`). Интерфейс на русском; единицы — км и ₽, даты в формате ДД.ММ.ГГГГ.

Версия 1 включает: машины (личные и общие), расходники с интервалами и шаблонами, учёт пробега, журнал замен, статусы и уведомления, звуки и голос, синхронизацию общих машин.

Вне рамок версии 1: фото чеков и деталей, учёт топлива, подключение к OBD-адаптеру, графики расходов, iOS и веб-версия.

## Стек и сборка

Приложение пишется на Kotlin с Jetpack Compose. Локальная база (Room) — главный источник данных, а Firebase служит только каналом синхронизации общих машин. Поэтому приложение полностью работает без интернета и без настроенного Firebase.

| Слой | Решение |
| --- | --- |
| Язык | Kotlin 2.x, JVM toolchain 17, Gradle Kotlin DSL + version catalog |
| Интерфейс | Jetpack Compose (Material 3 с полностью своей темой), Navigation Compose |
| Локальные данные | Room; настройки — DataStore |
| Фоновые задачи | WorkManager: проверка сроков и синхронизация |
| Синхронизация | Firebase Android SDK через BoM: Authentication (анонимный вход) + Realtime Database |
| Звук и голос | `SoundPool` для эффектов, системный `TextToSpeech` с русским голосом |
| QR-код гаража | ZXing core — только генерация картинки кода |
| DI | Без Hilt: простой ручной контейнер зависимостей |
| SDK | minSdk 26, targetSdk — последний стабильный на момент сборки |
| Идентификатор | `applicationId = "app.steamgarage"` — тот же указывается при регистрации в Firebase |

Структура пакетов:

```
app/src/main/java/app/steamgarage/
  data/     — сущности Room, DAO, репозитории
  domain/   — расчёт статусов и прогноз пробега (чистый Kotlin, без android.*)
  sync/     — синхронизация с Firebase
  notify/   — воркеры WorkManager, каналы уведомлений
  audio/    — звуки и голос
  ui/       — тема, общие компоненты, экраны
app/src/main/res/raw/   — звуковые эффекты (.ogg)
app/src/main/res/font/  — шрифты
app/google-services.json — конфиг Firebase (репозиторий приватный)
.github/workflows/build.yml
SPEC.md, DECISIONS.md, CHANGELOG.md, LICENSES-ASSETS.md
```

Сборка и установка:

- Если `google-services.json` нет, сборка всё равно проходит: плагин google-services подключается только при наличии файла, а в приложении синхронизация показана как «не настроена».
- Тип сборки `release` с R8, подпись ключом из GitHub Secrets (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`). Постоянный ключ нужен, чтобы обновления ставились поверх без потери данных. Нет секретов — подпись debug-ключом с предупреждением в логе.
- GitHub Actions: на каждый push — сборка и тесты; на тег `v*` — GitHub Release с файлом `steamgarage-<версия>.apk`, который удобно скачать прямо на телефоне.
- Версия приложения берётся из тега; `versionCode` растёт с каждым релизом.

## Данные

Данные устроены так, чтобы их можно было сливать с других устройств в любом порядке без потерь. Каждая запись живёт сама по себе, а производные величины — текущий пробег, дата последней замены, статус — вычисляются, а не хранятся.

**Поля синхронизации у каждой сущности:**

| Поле | Тип | Смысл |
| --- | --- | --- |
| `id` | String (UUID) | Создаётся на устройстве, никогда не меняется |
| `garageId` | String? | `null` — личная запись, не синхронизируется; иначе — код гаража |
| `updatedAt` | Long, мс | Время последнего изменения |
| `updatedBy` | String | Идентификатор устройства; разрешает ничью при равном времени |
| `deleted` | Boolean | Удаление — это пометка («надгробие»), а не стирание строки |
| `dirty` | Boolean, только локально | Изменение ещё не отправлено в облако |

**Сущности:**

| Сущность | Поля | Примечания |
| --- | --- | --- |
| Машина `Car` | название, марка, модель, год, госномер, VIN (необяз.), заметка, цвет значка | Название — обязательное, остальное по желанию |
| Расходник `Item` | `carId`, название, категория, интервал в км (необяз.), интервал в месяцах (необяз.), порог предупреждения в км и днях, артикул по умолчанию, заметка, активен | Нужен хотя бы один из двух интервалов |
| Замена `Service` | `carId`, `itemId`, дата, пробег, стоимость ₽ (необяз.), артикул/бренд, место (сервис или сам), заметка, `batchId` | Одно ТО на несколько расходников — несколько записей с общим `batchId` |
| Пробег `Mileage` | `carId`, дата, км, источник (вручную / из замены) | Текущий пробег — максимум по показаниям |
| Гараж `Garage` | код, название, дата вступления | Только локально; участники хранятся в облаке |

**Категории расходников:** масла, фильтры, жидкости, зажигание, ремни, тормоза, шины, электрика, другое. Категория определяет иконку и цвет таблички.

**Слияние:** при получении записи с тем же `id` побеждает версия с бо́льшим `updatedAt`, при равенстве — с бо́льшим `updatedBy`. Удалённая запись остаётся «надгробием» и тоже участвует в слиянии, поэтому удаление не «воскресает» после синхронизации. Время берётся с часов устройства; это решение записать в `DECISIONS.md`.

## Машины, расходники и замены

Основной сценарий: добавить машину → выбрать расходники из шаблона и поправить интервалы → указать, когда каждый меняли в последний раз → дальше только обновлять пробег и отмечать замены.

**Машины:**

- Добавление, редактирование и удаление (с подтверждением; удаление — «надгробие» вместе со всеми записями машины).
- Переключатель «Личная / Общая». Перевод в общую присваивает `garageId` машине и всем её расходникам, заменам и показаниям пробега и ставит их в очередь на отправку. Обратный перевод создаёт личную копию и предупреждает, что у других участников машина останется.

**Расходники:**

- При добавлении машины предлагается шаблон: отметить нужные пункты галочками, интервалы можно сразу поправить.
- Свой расходник: название, категория, интервал в км и/или в месяцах (срабатывает то, что наступит раньше), порог предупреждения, артикул по умолчанию.
- Сразу после добавления приложение спрашивает «Когда меняли в последний раз?» (дата и пробег) и создаёт из ответа первую запись замены. Если неизвестно — статус «нет данных», расходник подсвечен как требующий внимания.
- «Сохранить набор как шаблон» переносит набор расходников с интервалами на другую машину.

**Шаблон по умолчанию** (типовые значения, в интерфейсе подпись «проверьте по регламенту своей машины»):

| Расходник | Категория | км | мес. |
| --- | --- | --- | --- |
| Моторное масло | масла | 10 000 | 12 |
| Масляный фильтр | фильтры | 10 000 | 12 |
| Воздушный фильтр | фильтры | 20 000 | 24 |
| Салонный фильтр | фильтры | 15 000 | 12 |
| Топливный фильтр | фильтры | 30 000 | — |
| Свечи зажигания | зажигание | 30 000 | — |
| Ремень ГРМ | ремни | заполнить по регламенту | — |
| Ремень навесного оборудования | ремни | 60 000 | — |
| Тормозная жидкость | жидкости | — | 24 |
| Антифриз | жидкости | 60 000 | 36 |
| Масло КПП | масла | 60 000 | — |
| Тормозные колодки передние | тормоза | 30 000 | — |
| Щётки стеклоочистителя | другое | — | 12 |

**Пробег:**

- Кнопка «Обновить пробег» на карточке машины открывает ввод в виде барабанов одометра.
- Показание меньше текущего максимума — предупреждение с выбором «это ошибка в прошлых данных» или «отмена».
- Средний суточный пробег считается по показаниям за последние 90 дней (минимум 2 показания) и нужен для прогноза дат.

**Запись замены:**

- На карточке расходника рычаг «Заменено» открывает форму: дата (сегодня), пробег (текущий), стоимость, артикул/бренд (подставляется по умолчанию), место — сервис или сам, заметка.
- «Провести ТО» — выбрать несколько расходников и заполнить одну форму; создаются записи с общим `batchId`.
- Пробег из записи замены, если он больше текущего, автоматически добавляется в показания.
- Историю замен можно редактировать и удалять; видна по машине и по каждому расходнику, с суммой затрат за всё время и за год.

## Статусы и уведомления

У каждого расходника один из четырёх статусов; уведомление приходит при переходе в «Скоро» и в «Пора менять», а не каждый день. Срабатывает тот из интервалов (км или время), который наступит раньше.

**Расчёт** (модуль `domain`, чистые функции с тестами):

- Последняя замена — неудалённая запись `Service` этого расходника с наибольшим пробегом, при равенстве — с более поздней датой.
- По км: срок = пробег последней замены + интервал; остаток = срок − текущий пробег. Если известен средний суточный пробег — прогнозная дата = сегодня + остаток / средний пробег.
- По времени: срок = дата последней замены + интервал в месяцах; остаток в днях.
- Износ для манометра = максимум из долей «пройдено км / интервал» и «прошло дней / интервал».

| Статус | Условие | Цвет зоны манометра |
| --- | --- | --- |
| Нет данных | Нет ни одной записи замены | Стрелка лежит на упоре, табличка с вопросом |
| Норма | Остаток больше порогов | Латунная зона |
| Скоро | Остаток ≤ порога по км или по дням | Медно-оранжевая зона |
| Пора менять | Остаток ≤ 0; показывать, на сколько км/дней превышено | Красная зона, стрелка дрожит |

Порог по умолчанию: 10% интервала, но не меньше 500 км и 7 дней и не больше 2000 км и 30 дней. Меняется у каждого расходника и глобально в настройках.

**Уведомления:**

- Каналы: «Сроки замены», «Пробег», «Синхронизация» (последний — тихий).
- Ежедневная проверка через WorkManager в выбранное время (по умолчанию 10:00; допустим сдвиг на час). Внеочередная — после ввода пробега, записи замены и синхронизации.
- Уведомление только при смене статуса на «Скоро» или «Пора менять»; для «Пора менять» — повтор раз в 7 дней до записи замены. Состояние «уже уведомлено» хранится по расходнику локально.
- Несколько расходников одной машины объединяются в группу: «Веста: 2 расходника пора менять».
- Действия в уведомлении: «Заменено» (открывает форму замены) и «Напомнить через неделю». Нажатие открывает машину с подсвеченным расходником.
- «Обновите пробег»: если у машины есть интервалы по км, а показаний не было 14 дней (настраивается), действие открывает ввод пробега.
- Для общих машин каждое устройство уведомляет само; на каждом устройстве можно выключить уведомления по конкретной машине.
- Android 13+: разрешение на уведомления запрашивается при добавлении первого расходника, с экраном-объяснением перед системным диалогом.
- Один раз показать подсказку для Xiaomi/HyperOS и похожих оболочек: разрешить автозапуск и снять ограничения батареи, иначе фоновые проверки могут не срабатывать. Кнопка ведёт в настройки приложения.

## Синхронизация

Общие машины живут в «гараже» — общей папке в Firebase Realtime Database, доступ к которой даёт длинный код приглашения. Входить в аккаунт не нужно: приложение само получает анонимный аккаунт Firebase при первом запуске.

**Гараж:**

- «Создать гараж» генерирует код из 20 символов без похожих знаков (алфавит Crockford Base32), показывается группами по 4: `K7QM-2XRA-…`.
- Код показывается текстом и QR-кодом. QR содержит ссылку `steamgarage://join?code=…`; приложение регистрирует её, поэтому код можно отсканировать обычной камерой телефона. Кнопка «Поделиться» отправляет код через любой мессенджер.
- «Вступить в гараж»: вставить код или открыть ссылку. Устройство записывает себя в участники и загружает все общие машины.
- В версии 1 устройство состоит максимум в одном гараже.
- «Покинуть гараж»: удалить себя из участников; общие данные на устройстве — оставить как личные или удалить (выбор пользователя).
- «Имя на этом устройстве» (например, «Папа»): показывается в истории как автор записи — «Заменил: Папа».

**Структура в базе:**

```
/garages/{код}/members/{uid}   — { name, joinedAt }
/garages/{код}/cars/{id}
/garages/{код}/items/{id}
/garages/{код}/services/{id}
/garages/{код}/mileage/{id}
```

**Правила безопасности** (пользователь вставляет их в консоль Firebase): читать гараж могут только его участники, записать себя в участники может любой, кто знает код, писать данные — только участники.

```json
{
  "rules": {
    "garages": {
      "$gid": {
        ".read": "auth != null && data.child('members').child(auth.uid).exists()",
        "members": {
          "$uid": {
            ".write": "auth != null && auth.uid === $uid"
          }
        },
        "$other": {
          ".write": "auth != null && root.child('garages').child($gid).child('members').child(auth.uid).exists()"
        }
      }
    }
  }
}
```

**Алгоритм:**

- Источник правды — Room. Встроенный офлайн-кэш Firebase выключен (`setPersistenceEnabled(false)`), чтобы не было двух конкурирующих копий.
- Отправка: все записи с `dirty = true` уходят одним многопутевым `updateChildren`. После успеха флаг снимается, только если запись не менялась за время отправки.
- Получение: пока приложение открыто — слушатель изменений гаража в реальном времени. Каждая пришедшая запись сливается в Room по правилу из раздела «Данные».
- По кнопке «Синхронизировать» (рычаг в верхней панели) и в фоне раз в 6 часов при наличии сети (WorkManager): разовое чтение всего гаража, слияние, затем отправка. Данных мало, поэтому полное чтение допустимо.
- После синхронизации — короткий итог: «Получено 3, отправлено 1» и время последней успешной синхронизации.
- Ошибки: нет сети — изменения ждут в очереди; отказ в доступе (неверный код, исключение из гаража) — понятное сообщение; Firebase не настроен — вместо раздела синхронизации подсказка, как его настроить.

## Стимпанк-стиль

Стиль — викторианская мастерская: латунь, медь, тёмное дерево, эмаль и стрелочные приборы. Каждый декоративный элемент несёт смысл: манометр показывает износ расходника, рычаг выполняет действие, шестерни крутятся, только пока что-то происходит. Шестерёнок «для красоты» нет.

**Палитра** (токены темы; основная тема тёмная, есть дневная «пергаментная»):

| Токен | Тёмная | Дневная | Где |
| --- | --- | --- | --- |
| Фон | `#1E1611` тёмное дерево | `#EFE4CC` пергамент | Фон экранов |
| Поверхность | `#2B2019` | `#E2D3B3` | Карточки, панели |
| Латунь | `#B5A642` → `#E1C16E` (градиент) | то же | Рамки, таблички, стрелки |
| Медь | `#B87333` | `#9A5B28` | Акцент, рычаги |
| Текст | `#E8DCC4` | `#3B2A1A` | Основной текст |
| Текст вторичный | `#B9A88A` | `#6B5640` | Подписи |
| Норма | `#43B3AE` патина | `#2E7F7B` | Зона манометра |
| Скоро | `#D9822B` | `#B5651D` | Зона манометра |
| Пора менять | `#A4161A` эмаль | `#8E1216` | Зона и бейдж |
| Нет данных | `#7A7D80` сталь | `#5E6164` | Бейдж |

Все пары «текст — фон» проверяются на контраст не ниже 4,5:1 (WCAG AA).

**Шрифты** (только с лицензией OFL и полной кириллицей; исполнитель проверяет кириллические глифы и записывает лицензии в `LICENSES-ASSETS.md`): заголовки — Ruslan Display или Playfair Display SC; основной текст — Old Standard TT; цифры одометра и манометров — PT Mono.

**Компоненты** (рисуются в Compose Canvas и векторными ресурсами; чужую графику не использовать):

- **Манометр** — круглая шкала с рисками и тремя цветными зонами, стрелка с пружинной анимацией. В центре — остаток в км или днях цифрами одометра. Главный элемент карточки расходника.
- **Латунная табличка** — карточка с фаской, градиентом латуни, четырьмя заклёпками и «гравированным» текстом.
- **Рычаг** — главная кнопка действия («Заменено», «Синхронизировать»): срабатывает по нажатию или свайпу вниз, с анимацией хода, щелчком и короткой вибрацией.
- **Вентиль** — второстепенные кнопки; **тумблер** — переключатели.
- **Одометр** — ввод пробега барабанами цифр.
- **Шестерни** — индикатор загрузки и синхронизации.
- **Пар** — короткий клуб пара при сохранении, не дольше 1 с.
- **Трубы с муфтами** — разделители секций; нижняя навигация — латунная панель с гравированными иконками.
- Фон — процедурная текстура дерева или кожи с виньеткой, сгенерированная один раз и закешированная.

**Удобство важнее декора:** текст не мельче 14 sp, цифры пробега крупные, области нажатия не меньше 48 dp, учитывается системный масштаб шрифта. Если в системе отключены анимации — стрелки не дрожат, пар не идёт, шестерни заменяются статичной иконкой.

## Звуки и голос

Озвучка двух видов: короткие механические звуки на действия и голосовые фразы на важные события. Оба включены по умолчанию, настраиваются отдельно и молчат, когда телефон в беззвучном режиме (в настройках можно разрешить звук и в беззвучном).

**Звуковые эффекты:**

| Действие | Звук |
| --- | --- |
| Нажатие кнопки, вентиля, тумблера | Короткий металлический щелчок |
| Рычаг «Заменено» | Ход рычага, треск храповика, звонок колокольчика |
| Сохранение | Шипение пара, не дольше 0,8 с |
| Удаление | Глухой лязг |
| Ввод пробега | Тихий щелчок барабана на каждый шаг цифры |
| Синхронизация | Начало — раскрутка шестерён; успех — двойной звонок; ошибка — низкий гудок |
| Уведомление «Пора менять» | Паровой свисток — свой звук канала уведомлений |

Требования к звукам:

- Только лицензия CC0 (например, наборы Kenney) или синтез собственным скриптом `tools/gen_sounds.py` в репозитории — предпочтительно. Источник каждого файла — в `LICENSES-ASSETS.md`.
- OGG, моно, каждый файл до 50 КБ, пики не выше −3 dBFS, одинаковая громкость между файлами.
- Воспроизведение через `SoundPool` с предзагрузкой; ползунок громкости в настройках. На открытие экранов звуков нет — чтобы не надоедало.

**Голос** (системный `TextToSpeech`, русский язык, тон чуть ниже обычного):

| Событие | Примеры фраз |
| --- | --- |
| Записана замена | «Замена занесена в журнал», «Механизм обслужен» |
| Добавлена машина | «Новый экипаж в гараже» |
| Обновлён пробег | «Пробег записан» |
| Синхронизация прошла | «Гараж сверен», «Депеша доставлена» |
| Ошибка синхронизации | «Связь с гаражом прервана» |
| Открытие приложения при статусе «Пора менять» | «Внимание: пора менять моторное масло» — не чаще раза в день |

- Режимы в настройках: «Выкл», «Только важное» (по умолчанию: замена, синхронизация, предупреждения), «Все действия».
- Для каждого события 2–3 варианта фразы, чтобы не повторяться; фразы до 6 слов, в стиле механика из мастерской.
- Если русского голоса в системе нет — предложить установить его (системный экран установки голосовых данных) или выключить голос.
- Уведомления голосом не зачитываются: в фоне это навязчиво.

## Экраны

Нижняя навигация из четырёх вкладок: «Гараж», «Сроки», «Журнал», «Настройки». В верхней панели всех вкладок — рычаг синхронизации и шестерня-индикатор её состояния (видны, только если Firebase настроен и устройство в гараже).

| Экран | Что на нём |
| --- | --- |
| Первый запуск | Имя на этом устройстве; «Добавить первую машину» или «Вступить в гараж по коду» |
| Гараж | Латунные таблички машин: название, госномер, пробег цифрами одометра, мини-манометры трёх самых срочных расходников, значок «общая»; рычаг «Добавить машину» |
| Машина | Шапка с пробегом и кнопкой «Обновить пробег»; карточки расходников с манометром, статусом и остатком, отсортированы по срочности; «Провести ТО», «Добавить расходник», редактирование, переключатель «Личная / Общая» |
| Расходник | Большой манометр, интервалы и пороги, артикул, история замен этого расходника, рычаг «Заменено» |
| Форма замены | Нижняя панель: дата, пробег, стоимость, артикул, место, заметка; при «Провести ТО» — список отмеченных расходников |
| Ввод пробега | Диалог с барабанами одометра и текущим значением для сравнения |
| Сроки | Все расходники всех машин: сначала «Пора менять», затем «Скоро», затем «Норма»; фильтр по машине |
| Журнал | Все замены, новые сверху; фильтры по машине, категории и периоду; сумма затрат; для общих машин — кто записал |
| Настройки | Имя на устройстве; гараж (создать, вступить, код и QR, покинуть, время последней синхронизации); уведомления (время проверки, пороги, напоминание о пробеге, выключение по машине); звук (вкл., громкость, в беззвучном режиме); голос (режим); тема (тёмная, дневная, как в системе); резервная копия; «О приложении» и лицензии |

**Резервная копия:** экспорт всех данных в один JSON-файл через «Поделиться» и импорт из файла со слиянием по общим правилам. Это страховка, не зависящая от Firebase.

Пустые состояния не оставлять пустыми: на каждом экране без данных — короткая подсказка и одна кнопка следующего шага.

## Этапы и критерии приёмки

Шесть этапов; после каждого — APK в GitHub Releases, проверка пользователем на телефоне и только потом следующий этап. Каждый этап даёт работающее приложение.

0. **Каркас и стиль.** Проект, CI, тема (палитра, шрифты), базовые компоненты: табличка, рычаг, вентиль, тумблер, манометр с тестовыми данными, нижняя навигация.
   - APK из Releases ставится на телефон; экран-витрина компонентов выглядит как стимпанк и читается без напряжения в тёмной и дневной теме.

1. **Машины и расходники.** Room, машины, расходники, шаблон, «когда меняли в последний раз», пробег, запись замены, «Провести ТО», журнал.
   - Можно завести машину из шаблона, обновить пробег, отметить замену; после перезапуска приложения всё на месте.

2. **Статусы и уведомления.** Расчёт статусов, прогноз по среднему пробегу, экран «Сроки», уведомления с действиями, напоминание о пробеге, подсказка про автозапуск.
   - Тестовая машина с расходником, у которого остаток 300 км при пороге 500, даёт уведомление «Скоро» при ближайшей проверке, а повторно — не даёт.

3. **Звук и голос.** Все звуки из таблицы, голосовые фразы, настройки, беззвучный режим.
   - Каждое действие из таблицы звучит; в беззвучном режиме тишина; без русского голоса приложение предлагает установку и не падает.

4. **Синхронизация.** Анонимный вход, гараж, код и QR, ссылка-приглашение, правила, отправка и получение, фоновая синхронизация, «Покинуть гараж».
   - Два телефона в одном гараже: замена, записанная на первом, появляется на втором меньше чем за 10 секунд при открытом приложении.
   - Изменения, сделанные без сети, доходят после её появления; удалённая на одном телефоне запись не возвращается после синхронизации.

5. **Полировка.** Резервная копия, пустые состояния, анимации пара и шестерён, режим без анимаций, иконка приложения, экран «О приложении».
   - Полный сценарий «новая машина → шаблон → пробег → замена → уведомление → синхронизация» проходит без подсказок.


## Указания для Claude Code

Этот документ лежит в корне репозитория как `SPEC.md`. Первая команда — «Прочитай SPEC.md целиком и выполни этап 0»; дальше по одному этапу за раз.

**Порядок работы:**

- Перед этапом — короткий план и список затрагиваемых файлов. После — коммит, тег `v0.<этап>.0`, запись в `CHANGELOG.md` и пошаговая инструкция, что проверить на телефоне.
- Неясная деталь — выбрать простейший удобный вариант, записать в `DECISIONS.md` и продолжать. Пользователя спрашивать только о вкусовых вещах: как выглядит, как звучит.
- Пользователь — не программист: README и инструкции после этапов писать по шагам, без жаргона.
- Звуки, шрифты и графику брать только с лицензиями из раздела «Звуки и голос» и «Стимпанк-стиль»; каждый файл — в `LICENSES-ASSETS.md`.

**Код:**

- Логика статусов, прогноза и слияния — в пакете `domain` без зависимостей от Android.
- Все числа по умолчанию (пороги, интервалы шаблона, период фоновой синхронизации, 14 дней до напоминания о пробеге) — в одном файле `Defaults.kt` с комментариями.
- Синхронизация не блокирует интерфейс; любые ошибки сети и Firebase перехватываются и показываются человеческим текстом.
- Ни одной строки интерфейса в коде: все тексты — в `strings.xml`.

**Тесты (JUnit):**

- Статусы: только км, только время, оба интервала (срабатывает ранний), «нет данных», граничные значения порогов.
- Прогноз даты по среднему пробегу, включая случай с одним показанием.
- Слияние: побеждает новая версия; ничья по `updatedBy`; «надгробие» не воскресает; порядок прихода записей не влияет на результат.
- Уведомления: повторный запуск проверки не шлёт повтор; «Пора менять» повторяется через 7 дней.
- Резервная копия: экспорт → импорт даёт те же данные.

## Настройка (делает пользователь)

Всё это делается один раз, примерно за 20 минут, можно с телефона. Нужны аккаунт GitHub и аккаунт Google.

**GitHub и Claude Code:**

1. Зарегистрироваться на github.com и создать репозиторий: github.com/new → имя `steamgarage` → **Private** → галочка «Add a README» → Create repository.
2. В Claude Code подключить GitHub; при установке Claude GitHub App выбрать «Only select repositories» и отметить только `steamgarage`.
3. Экспортировать этот документ в Markdown и загрузить в репозиторий как `SPEC.md` (на GitHub: Add file → Upload files). Либо вставить текст в первое сообщение Claude Code и попросить сохранить его как `SPEC.md`.
4. Ключ подписи APK: на этапе 0 Claude Code создаст его и пошагово объяснит, какие четыре секрета добавить в репозиторий (Settings → Secrets and variables → Actions). Файл ключа в репозиторий не коммитится.

**Firebase** (порядок важен: база создаётся до скачивания конфига):

1. console.firebase.google.com → «Создать проект», Google Analytics выключить.
2. Build → Authentication → «Начать» → Sign-in method → «Анонимный» → включить.
3. Build → Realtime Database → «Создать базу» → регион Europe → «Заблокированный режим». На вкладке «Правила» заменить всё на правила из раздела «Синхронизация» → «Опубликовать».
4. Обзор проекта → «Добавить приложение» → Android → имя пакета `app.steamgarage` (SHA-1 не нужен) → скачать `google-services.json`.
5. Загрузить файл в репозиторий в папку `app/` (Add file → Upload files, в поле имени указать `app/google-services.json`). Если файл скачан до создания базы — скачать заново.

**Установка на телефоны:**

1. На странице репозитория → Releases → последний релиз → скачать `.apk` → открыть → разрешить установку из этого источника.
2. На первом телефоне: ввести имя → Настройки → «Создать гараж» → «Поделиться» кодом.
3. На двух других: установить тот же APK → ввести имя → «Вступить в гараж» → вставить код или отсканировать QR камерой.
4. Отметить нужные машины как «Общие» — они появятся у всех.
